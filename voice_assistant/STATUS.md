## Current architecture

- Local Ollama for conversation and tool selection; faster-whisper `small.en` for speech recognition; Kokoro `af_bella` for speech output.
- Routing: pending confirmations/follow-ups first, regex fast paths for simple commands, then local `llama3.2` JSON intent router (`intent_router.py`) for other utterances. Python validates and executes tool; LLM only classifies.
- Task-based chat routing also uses `qwen3.5:9b` for factual/reasoning when RAM allows and `gemma4:26b` for deep/high-complexity work. The model router and intent router serve different purposes.
- Microphone capture uses only Windows' current default input. Friday checks that default each listen cycle, calibrates on startup/device change, and dynamically tracks changing ambient noise (minimum startup threshold 300); faster-whisper VAD uses a more sensitive threshold for quiet speech.
- Friday has local speaker profiles. Enrollment starts only after the direct phrase `add voice profile`, obtains separate spoken consent for the voice embedding and optional personal details, then stores six normalized voice examples plus a centroid from samples of at least three seconds. It never retains raw recordings. A weak sample stays uncertain and is retried; a switch to another enrolled profile needs two consecutive strong matches. Private profile details/history/preferences stay gated while identity is uncertain. Optional details (interests, help wanted, reply style) are asked one at a time, read back, and stored only with confirmation under the matched speaker. Unknown voices remain unidentified; profile removal also removes details. Recognition only personalizes conversation and never authorizes actions.
- Speaker matching scores samples at least two seconds long; profile enrollment still requires six samples of at least three seconds. Current 0.620 threshold is unchanged pending voice comparisons across primary user and other speakers.
- Conversation turns and speaker profiles persist in PostgreSQL. Private history/preferences are loaded only for the current matched profile; unknown turns stay unassigned. Shared notes/ideas and household settings stay shared.
- New conversation turns and learned intent examples persist in PostgreSQL. Existing daily JSONL and learned-intent files remain unchanged as migration archives; Friday no longer writes new conversation logs there.
- Actions and facts come from deterministic tools. Chat-model action claims are guarded; untrusted/invalid intent output falls back to chat.
- `human.py` varies spoken acknowledgements and greetings.
